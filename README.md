---

## 这是什么

HexoDeck 是 Hexo 静态博客的桌面管理器。它不做主题、不替换引擎 —— 只是在你的 Hexo 站点外面套一层顺手的图形界面：写文章、管页面、调配置、看效果、推上线，都在一个窗口里完成。

**它不会要求你改变现有的站点结构**：直接用你已有的 Hexo 目录，站点里的配置、主题、插件、文章原样读入；应用只做增量编辑，改配置时注释与键顺序都保留。

## 功能一览

### 写作

- **文章与草稿**的新建、编辑、删除（删除进系统回收站），草稿一键转正式
- **CodeMirror 6 编辑器**：Markdown 语法高亮、格式化工具栏（标题 / 粗斜体 / 代码块 / 引用 / 列表 / 链接 / 图片 / 表格 / 撤销重做）、Ctrl+F 查找替换
- **图片随手贴**：粘贴、拖拽或选择文件，自动存入站点 `source/images/` 并插入链接
- **自动保存 + 实时预览**：停止输入即存（延迟可调），右侧分栏实时渲染
- **全文搜索**：标题 / 标签 / 分类 / 正文，命中处附摘录
- **参数侧栏**：分类、标签，以及可自由增删的 front-matter 参数

### 自定义参数：键值式 / 开关式 / 结构化

给文章加自己的 front-matter 字段，三种类型：

| 类型 | 界面形态 | 写入方式 |
|---|---|---|
| **键值式** | 文本输入框 | 原样写入字符串 |
| **开关式** | 可勾选的方框 | 勾选/取消写入你指定的值（默认 `true` / `false`，且作为 **YAML 布尔** 写入，模板里判断才正确） |
| **结构化** | YAML 编辑框（带高亮与实时校验） | 支持**嵌套对象**与**对象数组**，写回时序列化为规范的嵌套 YAML |

结构化类型专为「资源卡 + 多网盘链接」这类复杂 front-matter 设计：

```yaml
resource:
  enable: true
  type: mod
  version: v3.1.4
  links:
    - name: 蓝奏云
      url: https://example.com
      password: echo          # 提取码记得加引号，否则 YAML 会当成数字
    - name: 百度网盘
      url: https://example.com
      password: "1234"
```

- **模板一键套用**：内置 5 个骨架（游戏资源卡 / 多网盘链接 / 更新日志 / 视频嵌入 / 图片画廊），点一下即填入，改值即可；也可以把当前内容**存为自己的模板**反复使用
- **自动识别**：打开已有文章时，值为嵌套对象/对象数组的字段会自动按结构化处理 —— 不用手动改类型，也不会被压成字符串而损坏
- **语法校验**：YAML 有错时输入框标红并暂停自动保存，不会把坏数据写盘

参数定义（中文显示名、类型、开关写入值）按**站点**登记 —— 在 A 站配的参数不会跑到 B 站；新文章会自动带上本站在用的参数名，逐篇填值即可。

### 页面

Hexo 的独立页面（`about`、`tags`、`categories` 等）：

- 管理 `source/` 下不属于文章目录的 Markdown，**支持任意层级子目录**
- 新建时填标题、路径与初始参数 —— 路径即文件夹，自动创建 `about/index.md`；标题与参数里重复的键自动去重
- 编辑器与文章一致（分栏预览 / 自动保存 / Ctrl+S），front-matter 用 **YAML 输入框**直接编辑，带语法校验

### 自定义文集：把任意文件夹当文章库

侧栏「+ 自定义」可以添加多个**文集** —— 相当于给站点里某个文件夹单独开一个文章管理入口：

- **名称与图标自定义**：15 种内置矢量图标，也可以导入自己的图片（≤200KB）
- **目录随意**：站点根目录、其子目录、任意更深层级都可以
- 管理方式与「文章」完全一致：列表 / 新建 / 编辑 / 删除 + 自定义参数
- 适合放系列文章、随笔、笔记 —— 比如把 `source/_dynamics` 做成「说说」
- 文集按站点记忆；**移除文集只删入口，不动目录里的任何文件**

### 主题与插件

- **压缩包安装主题**：拖拽进窗口或浏览文件，支持 `.zip` / `.tar` / `.tar.gz` / `.tgz`，自动识别并规整目录结构
- 已装主题检测（`themes/` 目录 + npm 包）、一键切换（预览自动重启）
- **主题配置 YAML 编辑**，保存前语法校验；配置文件路径由你指定（覆盖文件或主题自带均可），按「站点 + 主题」分别记忆
- 内置 8 款热门主题市场，一键安装
- 插件列表（中文说明 + 配置键映射）、安装 / 卸载

### 预览

- **整屏 iframe 预览**主题渲染后的真实博客页面，可含草稿
- 站点文件一变，预览**自动刷新** —— 边写边看
- 一键在系统浏览器打开

### 构建与部署

- `generate` / `clean` / `deploy` 卡片式操作，实时运行日志（可清空）
- **发布前自动生成**：点部署会先跑一次 `generate`，避免把上一次的旧产物推上线
- **不再「假成功」**：从输出里识别 git 推送失败（仓库不存在、认证失败、推送被拒、分支为空等）并明确报错 —— hexo 本身在推送失败时不会返回非零退出码
- 部署配置不完整会提前提示（分支为空、仓库地址缺 `.git` 等），分支输入框带 main / master 快捷填入

### 站点配置

- **基础配置表单**：标题 / 副标题 / 作者 / 语言 / 时区 / URL / 永久链接 / 分页 / 资源文件夹等
- **站点图标**：在站点页点头像或拖入图片即可设置，写入站点 `source/favicon.*`，Hexo 生成时网站也会用上
- **配置文件直编**：YAML 高亮 + 查找替换 + 保存前校验。应用**不会自动定位**配置文件 —— 每个站点首次打开弹窗让你指定（可一键采用默认位置），之后按站点记住
- **写入安全**：行级替换编辑，注释、空行、键顺序原样保留；首次修改自动备份为 `_config.yml.hexodeck.bak`

### 统计

- 概览：文章 / 草稿 / 总字数 / 平均字数 / 标签 / 分类
- 活跃度：本周与本月新增、写作天数、最高产的一天、首篇与最新日期
- 最近 12 个月趋势、标签与分类排行、年度产出
- 内容特征：最长 / 最短文章，未分类 / 无标签文章提示

### 应用

- **多站点管理**：添加站点选文件夹，切换站点点卡片即切；站点信息、文集、参数定义、配置路径记忆**全部按站点隔离**
- **自绘标题栏**：无边框窗口，标题栏与界面同为玻璃圆角卡片，显示当前站点图标与名称；支持拖拽、双击最大化
- **路径可点击**：文章 / 页面 / 文集的文件路径与目录都能点，直接在资源管理器打开并选中
- 双主题：深空霓虹（暗）/ 冰白清新（亮），支持**跟随系统**自动切换
- 自动更新：启动时与每 6 小时检查 GitHub Releases，自动下载、重启生效
- 可选关闭到系统托盘、单实例锁（重复启动唤回已开窗口）
- 运行日志落地 `%APPDATA%/hexodeck/hexodeck.log`，设置页一键打开

## 快速开始

### 使用打包版（推荐）

从 [Releases](https://github.com/wanwuzhishi/HexoDeck/releases) 下载：

| 版本 | 说明 |
|---|---|
| **安装版** `HexoDeck-Setup-x.y.z.exe` | 向导式安装，可选目录；支持自动更新 |
| **绿色版** `HexoDeck-x.y.z-win.zip` | 解压即用，零安装、秒启动（U 盘亦可） |

> 绿色包请**先解压再运行**，不要在压缩包里直接双击。解压后启动不到 1 秒。

首次启动点击「添加站点」，选择你的 Hexo 博客根目录（含 `_config.yml` 的文件夹）即可。之后添加更多站点，在右栏站点卡片或站点页点「切换站点」。

> **无需安装 Node.js** —— 应用内嵌了 Hexo 引擎；站点里已有的 hexo 与插件会优先使用，与你的原有环境一致。

### 从源码开发

```bash
npm install
npm run setup:embed   # 安装内嵌 Hexo 引擎（resources/embed）
npm run dev
```

### 打包

```bash
npm run build:unpack  # 生成 dist/win-unpacked（快速验证）
npm run build:win     # 生成 NSIS 安装包 + 绿色包 zip
```

## 发布新版本

应用内置 [electron-updater](https://www.electron.build/auto-update)，以 GitHub Releases 为更新源：老用户启动时及每 6 小时自动检查，发现新版本自动下载、重启生效。

1. 升版本号：`npm version patch`（或 minor / major）
2. 打包：`npm run build:win`
3. 在 GitHub 以对应 tag 创建 Release，上传这些资产：

   | 资产 | 必需 | 用途 |
   |---|---|---|
   | `HexoDeck-Setup-X.Y.Z.exe` | ✅ | 安装包 |
   | `HexoDeck-Setup-X.Y.Z.exe.blockmap` | ✅ | 增量更新（只下变化部分） |
   | `latest.yml` | ✅ | 更新检查入口（版本号 + 哈希） |
   | `HexoDeck-X.Y.Z-win.zip` | 可选 | 绿色包 |

> ⚠️ `latest.yml`、安装包、blockmap 必须来自**同一次构建**，否则 sha512 校验不通过。

## 技术要点

- **Hexo 集成**：不在主进程内嵌 hexo 实例，而是 fork 子进程（Electron 的 Node 模式）承载；优先加载站点自带的 hexo 与插件，缺失时回退到应用内嵌引擎
- **配置写入**：行级替换编辑，只改目标键所在行，注释、空行、键顺序原样保留；保存前 YAML 校验，首改自动备份
- **构建串行队列**：generate / deploy 与 npm 操作串行执行，避免 `db.json` 冲突；npm 命令带 `--yes` 与 5 分钟看门狗
- **路径安全**：文集与页面的目录、文件路径均校验必须落在站点根目录内，拒绝 `..` 穿越
- **服务层不依赖 electron**：`src/main/services/` 可直接用 tsx 单测，无需启动界面
- **参数写入细节**：开关式参数的 `true`/`false` 以 YAML 布尔写入 —— 字符串 `'false'` 在主题模板里是真值，会导致开关失效；结构化参数以真实对象/数组交给主进程序列化，输出规范缩进的嵌套 YAML（不走 JSON 压缩，避免 `<img>` 等模板标签失配）

## 目录结构

```
src/
├─ main/            主进程：服务层（站点 / 文章 / 页面 / 文集 / 构建 / 预览 / 配置 / 日志 / 托盘）
│  └─ services/     各 Service 不依赖 electron，可 tsx 直接单测
├─ preload/         contextBridge 类型化 API
├─ renderer/        Vue 3 界面（三栏玻璃布局 + 双主题）
└─ shared/          主进程与渲染进程共享的 IPC 契约类型
resources/
├─ child/           hexo 子进程引导脚本（ELECTRON_RUN_AS_NODE）
└─ embed/           内嵌 Hexo 引擎（打包时解压出 asar）
scripts/
├─ smoke-services.ts  服务层验收脚本（npx tsx scripts/smoke-services.ts <站点目录>）
├─ make-icon.ps1      图标生成
└─ run.mjs            构建包装（Windows 下 TMP 重定向）
```

## 已知限制

- 目前**仅面向 Windows**（NSIS 安装包 / ZIP 绿色包）；macOS / Linux 可在 `electron-builder.yml` 中追加目标
- 安装 / 卸载插件需要本机有 Node.js —— 日常写作、预览、生成、部署都不需要
- 界面语言暂为中文
